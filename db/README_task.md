# 업무진행 평가(task.html) 설치·사용 안내

## 주소
- `task.html` (Google 로그인). 관리자는 `bangdw@gmail.com` 이며 첫 로그인 때 자동 등록됩니다. 비밀번호는 어디에도 저장하지 않습니다.

## 서버 설치 (운영 DB `asea-workspace`에는 이미 적용됨)
1. Supabase SQL Editor에서 `db/task_schema.sql` 실행 (여러 번 실행해도 안전). `tsk` 스키마와 `public.tsk_*` RPC 27개가 만들어집니다.
2. Edge Function `task-auth` 배포: `supabase/functions/task-auth/index.ts` (JWT 검증 켬). Google ID 토큰을 검증한 뒤 `tsk_login`(service_role 전용)을 호출합니다.
3. Google Cloud Console 의 OAuth 클라이언트(`config.js`의 googleClientId)에 승인된 JavaScript 원본 `https://bangdw-hash.github.io` 가 있어야 합니다(기존과 동일).

## 로그인·권한
| 권한 | 할 수 있는 일 |
|---|---|
| 관리자 | 전체. 구성원 승인·권한, 단계 이름, 평가 항목, 템플릿, 완전 삭제 |
| 부서장 | 같은 부서 업무 수정·단계 이동·평가 입력 |
| 담당자 | 본인 업무 수정, 본인 부서 업무 등록 |
| 열람 | 조회만 (참여자로 지정되면 상세 열람) |

- 새 계정은 첫 로그인 때 「승인 대기」가 되고, 관리자가 구성원 탭에서 부서·권한을 정해 「사용」으로 바꾸면 들어올 수 있습니다. 미리 등록도 가능합니다.
- 다른 부서 업무는 제목·단계·진행률·마감만 보입니다. 대상자 명단(개인정보)은 담당·참여자·부서장·관리자에게만 보입니다.
- 사후 평가는 부서장·관리자가 입력하고 담당자 본인과 평가 권한자에게만 공개됩니다.
- 세션은 12시간이며 서버에는 해시만 저장합니다. 탭을 닫으면 로그인이 풀립니다(sessionStorage).

## 기능
- 업무 유형: 행사 / 과정 / TF / 일반. 단계는 구분별 6단계(관리자가 이름 수정), 칸반·타임라인·표 전환, 기간·부서·담당·상태·단계 검색, 엑셀 내보내기·가져오기.
- 진행률은 체크리스트 완료율로 자동 계산(항목이 없으면 단계 기준). 상태: 마감 경과=지연, 설정한 일수 전부터 주의.
- 대상자: 명단 붙여넣기·엑셀 등록, 점수 순 선정, 선정자 안내 메일.
- 알림: 사이트 안 알림(담당·참여 지정, 단계 이동, 평가 등록)과 기한 알림(접속 시 계산). 메일은 로그인한 본인의 Gmail 로 직접 발송(`gmail.send` 권한을 발송 시점에 요청, 받는 사람마다 따로 발송, 한 번에 50명까지).
- 카카오톡 알림은 2차 개발 대상입니다. 자동 정시 발송(크론)도 2차입니다.

## 주의
- Google OAuth 앱이 「테스트」 상태이면 테스트 사용자로 등록된 계정만 로그인·Gmail 권한 허용이 가능합니다. 전 교직원이 쓰려면 앱 게시(또는 Workspace 내부 앱) 설정이 필요합니다(Google Cloud Console).
- 대상자 정보는 개인정보입니다. 업무가 끝나면 삭제하십시오.
- DELETE 문은 plpgsql 안이 아니라 `tsk.drop_*` SQL 함수로 분리해 두었습니다(운영 DB 적용 도구의 시간 초과 회피 목적).
