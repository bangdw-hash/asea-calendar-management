   - `budget_schema_3.sql` 공개 RPC (접속 · 부서)
   - `budget_schema_4.sql` 관리자 RPC · 실행 권한

2. 시드 데이터를 **번호 순서대로, 파일마다 새 쿼리로 한 번씩만** 실행합니다. (용량이 커서 한 번에 붙여넣으면 잘릴 수 있어 6개로 나누었습니다)

3. 관리자 비밀번호를 등록합니다. 아래 `<관리자 비밀번호>`만 바꿔 실행합니다. 이 값은 저장소에 두지 않습니다.

## 결재 QR 집행 연동 (budget_schema_5.sql)

기안문 결재와 예산 집행을 연결합니다. 결재시스템과는 별도로 동작하며, 결재번호는 사람이 입력합니다.

1. 부서: 「결재 QR · 집행」 탭 → 새 QR 발급(건명, 집행 예정 줄: 예산 항목 또는 귀속 미정) → QR 이미지를 기안문에 삽입
2. 결재 후 누구나 스캔(`budget-qr.html?t=...`, 로그인 불필요) → 결재번호(필수, 중복 차단) 입력, 금액 확인·수정 → [반영] (**1회만**)
   - 결재 기준액과 다르면 사유 필수, 예산을 넘으면(마이너스) 확인 + 사유 필수
   - 반영하면 `bgt.spend`에 즉시 들어가 부서 화면에 보임. 귀속 미정 줄은 「미배정」으로 기록
3. 재스캔: 「이미 반영된 내역입니다」 + 현재 예산·집행 누계·잔액·집행 내역 표시. [수정반영]은 해당 QR의 부서 계정 또는 관리자 로그인 후 사유를 적고 수정
4. 관리자: 「결재 QR·집행」 탭 → 미배정 배정(기존 항목 이관 / 미편성 신규 항목 / 예비비 7.2.1 + 명목), 조정 필요(미편성·예산 초과), 결재액 불일치, 예비비 사용 내역(엑셀), 무효 처리
5. 모든 발급·반영·수정·배정·무효·직접 수정은 `bgt.ticket_events`에 변경 전후 값과 함께 쌓이며 수정·삭제할 수 없습니다(트리거). 접속 IP는 해시로만 저장합니다.

- 「현재 예산」은 `bgt.lines.base_amount`(전년도 확정 예산)입니다. 신규 편성(미편성) 항목은 0원으로 시작합니다.
- QR 토큰은 서버 난수(144비트)이며, 토큰을 아는 사람은 최초 1회 반영을 할 수 있습니다. QR 이미지는 결재 문서 안에서만 유통하십시오.
- 로그인 없이 보이는 정보는 해당 QR의 항목(예산·집행 누계·집행 내역)으로 한정되며, 거래처명은 로그인한 부서·관리자에게만 보입니다.

## 보안 구조

- 모든 테이블은 `bgt` 스키마(API 비노출) + RLS 활성 + `anon`/`authenticated` 권한 회수. 브라우저(anon 키)는 직접 접근할 수 없습니다.
- 브라우저는 `public.bgt_*` RPC(SECURITY DEFINER)만 호출하며, 부서/관리자 로그인 후 발급된 12시간 토큰(해시로 저장)을 서버가 검증합니다.
- 부서 비밀번호는 bcrypt 해시(검증용)와 서버 키 암호화본(관리자 조회용)으로 저장합니다. 암호화 키는 `bgt.secret`에만 있고 API로 노출되지 않습니다.
- 로그인 5회 실패 시 부서 10분 / 관리자 15분 잠금. 조회·초기화·변경은 `bgt.log`에 기록됩니다.
